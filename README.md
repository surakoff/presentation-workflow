# Работа с презентациями

Командный комплект для сборки презентаций по собственным шаблонам. Руководства подходят для ручной работы, а проектный скилл использует их в Codex. Макеты, брендовые ассеты, данные и шрифты задаются для каждой презентации.

## Быстрый старт

1. Скачайте или клонируйте репозиторий и откройте его корень в Codex. Для ручной работы начните с руководства нужного формата.
2. Заполните [бриф](templates/brief.md). Укажите ссылку на свой шаблон или исходный файл, используемые шрифты, рабочее место сохранения и нужный результат.
3. Проверьте доступность инструментов по [карте зависимостей](.agents/skills/presentation-art-director/references/tools.md). Для Figma используйте свой аккаунт и предоставленный доступ, для визуальной приёмки PPTX — целевой PowerPoint.
4. Запустите работу обычным запросом или укажите скилл `$presentation-art-director`.

> Используй $presentation-art-director. Возьми мой шаблон [ссылка] и шрифты, указанные в брифе. Собери два пробных редактируемых слайда в согласованном файле Figma. После согласования экспортируй их в PPTX и проверь рендеры, текст, фигуры и клики. Оптимизацию для PDF и анимацию выполняй по отдельному запросу.

Папка `.agents/skills/presentation-art-director/` содержит скилл и его руководства. Её можно перенести в другой проект целиком. Для подключения сторонних скиллов используйте карту зависимостей, которая находится внутри этой папки.

## Обновление

Стабильные версии и отдельный ZIP скилла публикуются в [GitHub Releases](https://github.com/surakoff/presentation-workflow/releases/latest). Подробности доступны в [истории изменений](.agents/skills/presentation-art-director/CHANGELOG.md).

Скилл сам проверяет GitHub перед первой задачей в новом чате и затем через каждые 20 рабочих сообщений пользователя. При выходе новой версии GPT объясняет, что улучшилось, и предлагает её установить. Достаточно ответить «да» или «ок». Вне очереди обновление можно запустить командой «Обнови presentation-art-director».

В браузерном Work, если чат не может установить новую копию, скачайте ZIP из релиза и загрузите его в **Plugins → Skills**. После загрузки проверьте номер версии. Изменения из GitHub в загруженную копию автоматически не попадают.

В Codex для отдельной установки используйте `$skill-installer` с путём `.agents/skills/presentation-art-director` и тегом релиза вместо `main`. Если папка уже существует, сначала сохраните её вне каталогов, из которых Codex загружает скиллы. В клоне репозитория обновите ветку командой `git pull`.

## Проверка комплекта

```sh
python scripts/check_repo.py
```

Проверка обнаруживает отсутствующие руководства, битые локальные ссылки в наших инструкциях и случайно включённые рабочие артефакты. Содержательную проверку пайплайна проведите на своей презентации в целевых инструментах. На GitHub эта команда запускается при изменениях репозитория.

Для проверки структуры готового файла запустите `python scripts/inspect_pptx.py path/to/file.pptx`. Скрипт покажет явно заданные семейства в текстовых фрагментах, записи о встроенных шрифтах и действия по клику. Унаследованные шрифты и начертания дополнительно сверяйте в PowerPoint. Адреса могут вести к рабочим материалам, поэтому сохраняйте отчёт рядом с проектом.

Поставляемые сторонние скиллы и их лицензии перечислены в [THIRD_PARTY.md](THIRD_PARTY.md).

Для контрольного прогона у коллеги используйте установленный ZIP и его обычное подключение. В Figma Design удлините текст в тестовой карточке и проверьте сетку и начертания. В PowerPoint проверьте правку абзаца, перенос целой карточки, масштабирование векторного логотипа, область клика кнопки и открытие на машине без исходной гарнитуры. Для Motion перечитайте Play once на каждом созданном таймлайне; для PDF проведите полный цикл по оригиналу. Для обратной связи отправьте согласованный тестовый скриншот из браузерного Work и сверьте вложение со стороны владельца. Для обновления проверьте переход со старой установки через согласие до активного номера версии. Фиксируйте, в каком аккаунте, приложении и на каком файле выполнен каждый тест.
