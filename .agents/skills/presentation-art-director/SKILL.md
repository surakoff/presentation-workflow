# Арт-дирекшен презентаций

Опирайся на шаблон, брендбук, шрифты и материалы, которые указал пользователь. Уточни цель, аудиторию, формат выдачи и степень редактируемости, если это влияет на работу. Явные требования пользователя и его согласованный шаблон определяют дизайн. Если шаблона нет и задана свободная стилистика, разработай согласованное направление по брифу.

1. Собери факты и источники. Определи задачу каждого слайда и подбери макет по функции, плотности контента и геометрии. Сохрани существенные цифры, оговорки и терминологию. Сопоставь ключевые слайды с реальными рендерами ближайших примеров шаблона.
2. Для сборки в Figma прочитай [правила Figma Design](references/figma-design.md). Подтверди источник и рабочее место записи. До сборки проверь через Figma MCP в рабочем подключении точное семейство и каждое нужное начертание. Если шрифт недоступен, назови недостающие начертания и объясни, куда их загрузить. Дождись успешной повторной проверки перед сборкой затронутых слоёв. Сохраняй исходные шрифты и настройки типографики.
3. Для редактируемого PPTX прочитай [правила PowerPoint](references/powerpoint.md). Используй исходную редактируемую версию, если задача требует сохранения структуры. Открой итог в целевом PowerPoint и отдельно проверь внешний вид, редактируемость и клики. Архив шрифтов приложи только по запросу.
4. Для запрошенной оптимизации под PDF прочитай целиком [единые правила оптимизации](references/pdf-optimization.md). Выполняй её как отдельную операцию в рабочей копии. Веди реестр обработки и проверки каждого блока.
5. Для анимации прочитай [правила анимации](references/motion.md). Определи целевой формат и как должен запускаться показ. Ожидание между слайдами, запуск эффектов внутри слайда и зацикливание задаются отдельно.
6. Для зависимостей смотри [карту инструментов](references/tools.md). Подключай только то, что нужно для выбранного маршрута. Если недоступна проверка в целевой программе, прямо укажи предел выполненной проверки.

В Figma сначала продумай дерево слоёв по выбранному макету. Сохраняй его рабочий Auto Layout. Для новых блоков применяй Auto Layout локально, если элементы должны перестраиваться при редактировании. По умолчанию оставляй верхний фрейм слайда свободным. Перед выдачей проверь дерево через Figma MCP и отдельно оцени отступы, выравнивание и оптический баланс по рендерам.

Сравни итоговые рендеры с оригиналом и перепроверь однотипные объекты после системного исправления. Отдай только запрошенные результаты, укажи остаточные отличия и предоставь рабочие ссылки или пути к файлам.

При запросе на обновление сравни версию установленной копии с [последним релизом на GitHub](https://github.com/surakoff/presentation-workflow/releases/latest). По [истории изменений](CHANGELOG.md) новой версии кратко перечисли изменения после установленной версии. Если старая версия неизвестна, укажи это и перечисли изменения последнего релиза. Подтверждай обновление только после установки новой копии. Если установка из чата недоступна, дай ссылку на архив релиза и шаг загрузки.
