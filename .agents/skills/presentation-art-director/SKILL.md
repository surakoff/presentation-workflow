# Арт-дирекшен презентаций

На просьбу оставить обратную связь, узнать, что с обращением, или разобрать отзывы примени [порядок работы с обращениями](references/feedback.md). Этот маршрут работает и без активной задачи по презентации.

Опирайся на шаблон, брендбук, шрифты и материалы, которые указал пользователь. Уточни цель, аудиторию, формат выдачи и степень редактируемости, если это влияет на работу. Явные требования пользователя и его согласованный шаблон определяют дизайн. Если шаблона нет и задана свободная стилистика, разработай согласованное направление по брифу.

1. Собери факты и источники. Определи задачу каждого слайда и подбери макет по функции, плотности контента и геометрии. Сохрани существенные цифры, оговорки и терминологию. Сопоставь ключевые слайды с реальными рендерами ближайших примеров шаблона.
2. Для сборки в Figma прочитай [правила Figma Design](references/figma-design.md). Подтверди источник и рабочее место записи. До сборки проверь через Figma MCP в рабочем подключении точное семейство и каждое нужное начертание. Если шрифт недоступен, назови недостающие начертания и объясни, куда их загрузить. Дождись успешной повторной проверки перед сборкой затронутых слоёв. Сохраняй исходные шрифты и настройки типографики.
3. Для редактируемого PPTX прочитай [правила PowerPoint](references/powerpoint.md). Используй исходную редактируемую версию, если задача требует сохранения структуры. Открой итог в целевом PowerPoint и отдельно проверь внешний вид, редактируемость и клики. Архив шрифтов приложи только по запросу.
4. Для запрошенной оптимизации под PDF прочитай целиком [единые правила оптимизации](references/pdf-optimization.md). Выполни полный цикл в отдельной копии. Запусти включённую в руководство проверку по оригиналу и копии, исправь открытые ошибки и проверь реальные рендеры каждого блока. После локального сбоя продолжай доступную работу.
5. Для анимации прочитай [правила анимации](references/motion.md). Для движения объектов внутри слайда в Figma применяй нативный Motion после проверки доступа к таймлайну. Прототип используй для согласованных переходов между слайдами или когда пользователь запросил именно прототип.
6. Перед каждой операцией выбери нужные вспомогательные скиллы по [карте инструментов](references/tools.md), загрузи их инструкции и примени их к соответствующей задаче. Выполни операцию подходящими инструментами и проверь результат. Если скилл или нужная функция недоступны, сообщи о конкретном ограничении и продолжай независимые шаги.

В Figma сначала продумай дерево слоёв по выбранному макету. Сохраняй его рабочий Auto Layout. Для новых блоков применяй Auto Layout локально, если элементы должны перестраиваться при редактировании. По умолчанию оставляй верхний фрейм слайда свободным. Используй единую систему полей и отступов для существующих и новых слайдов. Сначала бери её из гайда или презентации, а при свободной сборке задай до начала работы. Перед выдачей проверь дерево через Figma MCP и отдельно оцени отступы, выравнивание и оптический баланс по рендерам.

Сравни итоговые рендеры с оригиналом и перепроверь однотипные объекты после системного исправления. Отдай только запрошенные результаты, укажи остаточные отличия и предоставь рабочие ссылки или пути к файлам.

## Проверка обновлений

При первом использовании скилла в каждом чате проверь релиз до начала работы над запросом. Повтори проверку перед ответом на каждое 20-е следующее рабочее сообщение пользователя по скиллу. Отсчитывай интервал от последней попытки, включая явную команду «Обнови presentation-art-director». Учитывай только сообщения пользователя по задаче. При неясной истории после сокращения контекста считай от последней подтверждённой проверки или начала доступного отрезка.

Прочитай metadata.version активной копии. Сделай короткий запрос на чтение к [GitHub API последнего стабильного релиза](https://api.github.com/repos/surakoff/presentation-workflow/releases/latest) и сравни три числовые части tag_name после префикса v. Если API недоступен, используй тег на [странице стабильного релиза](https://github.com/surakoff/presentation-workflow/releases/latest). Для автоматической проверки достаточно публичного доступа на чтение.

- Версии совпали: продолжай задачу молча. При явной команде подтверди актуальную версию.
- Если релиз новее, один раз для данного тега за чат назови версию, объясни конкретную пользу по истории изменений и предложи «Установить?». Продолжай текущую задачу, пока пользователь решает. Ответ «да», «ок» или «ставь», однозначно относящийся к предложению, разрешает установить предложенную версию. Явная команда «Обнови presentation-art-director» сразу разрешает обновление. После согласия установи версию доступным способом и проверь metadata.version активной копии. При отказе продолжай работу с текущей версией. Если установка из чата недоступна, дай ссылку на ZIP и путь Plugins → Skills.
- Если локальная версия новее, сохрани её. Если версию определить не удалось или GitHub недоступен, продолжай работу с доступной копией. Кратко укажи ограничение один раз за чат или в ответ на явный запрос. Следующая плановая попытка — через обычный интервал.
